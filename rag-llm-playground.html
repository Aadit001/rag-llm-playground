The Big Picture

An LLM (Large Language Model) is a neural network that predicts the next token given previous tokens. RAG wraps an LLM with a retrieval step so it can answer using your documents instead of only what it memorized during training.

How a plain LLM answers

Your prompt (text)→ Tokenizer→ Embeddings→ Transformer layers (attention)→ Logits→ Sampling→ Next token

The last two steps repeat token-by-token until a stop condition. Explore each stage in tabs ②–④.

How RAG answers

Question→ Embed query→ Vector search over chunks→ Top-k context→ Prompt = context + question→ LLM→ Grounded answer

RAG = Retrieve relevant text, then Augment the prompt, then Generate. Explore in tab ⑤.

Why RAG exists

  • LLMs have a training cutoff — no knowledge of recent/private data.
  • Hallucination: models invent facts. Grounding in real text reduces this.
  • Updateable: change the documents, not the model weights.
  • Citations: you can show where an answer came from.

The variables you'll meet

  • temperature, top_k, top_p — randomness controls
  • chunk_size, overlap — how docs are split
  • k — how many chunks to retrieve
  • embedding dim — vector length
  • cosine similarity — the match score
  • context window — token budget

② Tokenizer — turning text into numbers

LLMs don't see letters. Text is split into tokens (word pieces), and each token maps to an integer token ID from a fixed vocabulary. This toy uses a simple word/sub-word splitter so you can see the idea.

Real tokenizers (BPE, WordPiece, SentencePiece) learn merges from data. Fewer tokens = cheaper + fits more in the context window.

A rough rule for English: 1 token ≈ 4 characters ≈ ¾ of a word. A "4,000 token context" is roughly 3,000 words.

③ Embeddings — meaning as a vector

An embedding turns a piece of text into a list of numbers (a vector) so that similar meanings sit close together in space. RAG retrieval is just finding the vectors nearest to your query vector.

Real models use 384, 768, 1536… dimensions. More dims = more nuance, more storage, slower search. Here we keep it tiny and deterministic so you can see the vector.

Cosine similarity —

Cosine similarity ranges from -1 (opposite) to 1 (identical direction). RAG ranks chunks by this score.

The cosine formula

cos(A,B) = (A · B) / (‖A‖ × ‖B‖)

Dot product of the two vectors, divided by the product of their lengths. It measures the angle between them, ignoring magnitude — so "cat" and "CAT CAT CAT" point the same way.

④ LLM Sampling — how the next word is chosen

The model outputs a raw score (logit) for every token in the vocabulary. Softmax turns logits into probabilities. Then temperature, top-k, and top-p decide how adventurous the pick is. Press Sample repeatedly to feel the randomness.

0 = greedy/deterministic (always the top token). High = flatter distribution, more creative & more random.

⑥ Glossary — every variable, in plain English

    

      
Token
A word-piece. The atomic unit an LLM reads and writes.

      
Vocabulary
The fixed set of all tokens a model knows (e.g. ~50k–200k).

      
Token ID
Integer index of a token in the vocabulary.

      
Embedding
A vector of floats representing meaning. Similar text → nearby vectors.

      
Embedding dimension
How many numbers per vector (384/768/1536…). Higher = more nuance.

      
Cosine similarity
Angle-based score (−1…1) measuring how aligned two vectors are. The core retrieval metric.

      
Vector database
Store optimized for nearest-neighbor search over embeddings (e.g. FAISS, Pinecone, pgvector).

      
Logit
Raw, unnormalized score the model assigns each candidate next token.

      
Softmax
Function turning logits into a probability distribution that sums to 1.

      
Temperature
Scales logits before softmax. Low = confident/deterministic, high = random/creative.

      
Top-k
Only sample from the k most probable tokens.

      
Top-p (nucleus)
Only sample from the smallest group of tokens whose probabilities sum to p.

      
Greedy decoding
Always pick the single highest-probability token (temperature = 0).

      
Context window
Max tokens the model can read at once (prompt + retrieved context + answer).

      
Chunk
A slice of a document stored and retrieved as one unit.

      
Chunk overlap
Shared words between adjacent chunks so meaning isn't cut off.

      
k (retrieval)
Number of chunks pulled back for a query.

      
Similarity threshold
Minimum score a chunk needs to be included.

      
Prompt augmentation
Injecting retrieved context into the prompt before generation — the "A" in RAG.

      
Grounding
Forcing answers to come from supplied sources, reducing hallucination.

      
Hallucination
When a model states something false or unsupported with confidence.

      
Training cutoff
Date after which the base model knows nothing — the gap RAG fills.
